02 · WHY
解决什么

demo 不是空中楼阁
代码要跟线上对得上

凭描述生成的 demo,交付时前端要重写一遍 —— 因为 class 名、CSS 变量、布局结构都跟生产代码不一致。这个 skill 用源文件组装,交付即可用。

BEFORE
凭文档猜的 demo
  • class 名自由发挥,前端重写一遍
  • 颜色硬编码,改主题要全文搜索
  • 组件凭印象拼,跟线上差很远
  • 交付即返工,demo 等于白做
→
AFTER
用源文件组装
  • 读真实模块,class 跟线上一致
  • CSS 变量从 tokens 里拿,改主题改一处
  • 组件直接复制粘贴,样式天然准确
  • 交付即可用,前端零返工

05 · DO & DON'T
写法对照

写法对照

这个 skill 跟"自由发挥写 demo"的根本差别 —— 体现在每一处写法的选择上。

✓ GOOD
  • 读 demo-source/ai-site/modules/ 里的真实文件
  • class="qt-ai-create-box"(跟线上一致)
  • color: var(--qt-primary) 用 tokens
  • 布局用 references/layouts.md 里的 4 种模板
× BAD
  • 凭 SKILL.md 的描述自己重写一个差不多的
  • class="create-area"(自创命名)
  • color: #d8ff00(硬编码,改主题要全文替换)
  • 自己想一个布局,跟线上四不像
06 · HOW
执行流程

执行流程

4 步从触发到交付,每一步都有明确的输入和输出。

01
确认产品线 —— 千图AI(AI 创作页)还是智能设计(画布编辑器)?选错了源文件目录就走偏了。
02
读 references/ 下对应的 tokens 和 components 文档,把要用的 CSS 变量和 class 名先记下来。
03
从 demo-source/ 抓所需模块的 HTML/CSS,直接复制不修改 —— 修改 = 跟线上不一致。
04
拼装成完整 demo,用 layouts.md 里的布局模板包起来,交付前端开发。
